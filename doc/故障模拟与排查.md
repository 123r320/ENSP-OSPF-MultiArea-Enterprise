## 故障模拟与排查

本项目设计多组故障场景，用于练习 OSPF 排障，面试重点内容
## 故障一、OSPF 接口宣告区域错误

### 故障现象

R2 和 R1 的 OSPF 邻居无法建立，邻居状态停留在 Init 状态，无法到达 Full。分支网段路由无法学习。

### 故障原因

R2 连接 R1 的 G0/0/1 接口，错误宣告进 Area0，正确应该宣告进 Area1。OSPF 邻居建立要求直连接口两端 OSPF 区域号必须一致。

### 排查步骤

1. `display ospf peer brief` 查看邻居状态，发现状态卡在 Init
2. `display ospf interface GigabitEthernet0/0/1` 查看该接口所属 OSPF 区域
3. 对比 R1、R2 两端接口 OSPF 区域，发现区域号不一致

### 修复命令

修改 R2，将互联接口宣告回 Area1，邻居状态变为 Full。

## 故障二、取消 ABR 路由汇总

### 故障现象

骨干区域 Area0 的 LSDB 条目大量增加，出现分支网段明细路由，路由器 LSDB 开销变大，增加设备 CPU 与内存压力。

### 故障原因

R1 作为 ABR 删除 abr-summary 汇总命令，不再生成汇总 Type3 LSA，分支明细 LSA 全部泛洪进入骨干 Area0。

### 排查步骤

1. `display ospf lsdb` 在 R1 查看 LSDB，观察 LSA 数量
2. 在 R1 查看 OSPF 区域配置，确认 abr-summary 是否配置

### 修复命令

ospf 1
area 1
abr-summary 192.168.20.0 255.255.255.0
area 2
abr-summary 192.168.30.0 255.255.255.0

## 故障三、修改接口 cost，改变 OSPF 选路

### 故障现象

路由表优选路径发生变化，链路开销值改变，流量转发路径切换。

### 原理

OSPF cost 计算公式：cost = 100M / 接口带宽；cost 在入方向计算，cost 越小越优先。

### 模拟操作

修改 R1 G0/0/1 接口 cost：
interface GigabitEthernet0/0/1
ospf cost 100

### 现象

该链路开销变大，优先级下降，路由器会自动选择 cost 更小的链路作为主路由。

### 排查步骤

`display ip routing-table protocol ospf` 查看路由下一跳变化。

### 修复命令

interface GigabitEthernet0/0/1
undo ospf cost

## 故障四、OSPF 邻居无法建立（通用场景）

### 故障现象

路由器接口物理状态 UP，但 OSPF 邻居关系无法正常建立，无法学习到对端的路由条目。

### 故障原因

两端接口 OSPF 区域配置不一致、接口未开启 undo shutdown、互联两端 IP 不在同一网段、接口网段没有在 OSPF 进程中宣告。

### 排查步骤

1. `display interface GigabitEthernet 0/0/0` 查看接口物理和协议状态，确认接口已经开启
2. 查看两端互联接口 IP 地址，确认 IP 属于同一个网段
3. `display ospf interface GigabitEthernet 0/0/0` 核对接口所属 OSPF 区域号
4. `display ospf 1 configuration` 检查网段宣告是否配置

### 修复命令

根据查出问题对应修改，接口关闭就 undo shutdown；IP 错误修改 IP；区域不一致修改 OSPF 区域；漏宣告就补充 network 网段宣告，配置完成后邻居正常建立。

## 故障五、同区域互通，跨 Area 区域不通

### 故障现象

同一个 Area 内 PC 可以互相 ping 通，跨不同区域的终端无法通信，骨干区域缺少对应的跨区域路由。

### 故障原因

多区域 OSPF 规范不满足，非骨干区域没有连接 Area0 骨干区域；ABR 路由器配置缺失；骨干区域网段漏宣告。

### 排查步骤

1. 查看拓扑，确认所有非骨干区域是否直接连接 Area0 骨干
2. 在 ABR 上执行`display ospf brief`，确认 ABR 身份正常
3. `display ip routing-table protocol ospf` 检查骨干区域是否存在分支路由

### 修复命令

调整拓扑或修改区域配置，保证所有非骨干区域挂靠 Area0；补充骨干网段的 OSPF network 宣告，完成后跨区域路由正常传递，全网互通。

## 故障六、OSPF 邻居正常，但部分网段路由缺失

### 故障现象

OSPF 邻居状态 Full，邻居建立成功，但是路由表里缺少部分业务网段，对应网段无法访问。

### 故障原因

业务接口没有加入 OSPF 进程、网段宣告的反掩码写错、多台路由器 Router-ID 重复冲突。

### 排查步骤

1. `display ospf 1 configuration` 检查业务网段是否完成宣告
2. 核对 network 命令里的网段和反掩码书写是否正确
3. `display ospf router-id` 查看所有路由器的 router-id，检查是否出现重复

### 修复命令

补充缺失的 network 宣告；修正错误的反掩码；修改冲突路由器的 router-id，重启 OSPF 进程，设备接收完整 LSA，路由条目恢复。

## 故障七、下联终端收到大量 OSPF Hello 报文

### 故障现象

PC 终端抓包可以收到 OSPF Hello 报文，产生多余协议报文，造成不必要的报文开销。

### 故障原因

连接 PC 的路由器接口没有配置 silent-interface，接口持续向外发送 OSPF Hello 报文，尝试建立邻居。

### 排查步骤

1. `display ospf 1 silent-interface` 查看静默接口列表
2. 在路由器下联接口抓包，确认存在 OSPF Hello 报文

### 修复命令

ospf 1
silent-interface GigabitEthernet 0/0/1
配置后接口不再发送 Hello 报文，网段路由仍然可以正常宣告到 OSPF 网络。

## 通用标准化排错流程

整体遵循从底层到上层的排查逻辑：先检查物理接口状态，再核对二层 IP 配置，接着排查 OSPF 邻居状态，然后检查路由表与 LSA 数据库，最后测试终端全网连通性，快速定位并解决绝大多数园区网 OSPF 故障。
